# Local binary upload contract

All six legal-source formats DOC/DOCX/HTML/PDF/TXT/XHTML use the same canonical Knowledge original-attachment owner. CSV/XLSX are optional technical catalogues and cannot masquerade as legal documents. Genuine RAR4/RAR5/ZIP archives enter durable batch import. Folder/multiple-file paths retain strict normalized relative identity; no Drive or spreadsheet is required.

The backend selects versioned object identity and governed upload policy. The browser streams whole-file and per-part digests in bounded workers, transfers signed parts without application credentials, and preserves an opaque session identity for resume. Server-confirmed receipts, whole-file digest/size, exact object version and real isolated antivirus must pass before mapping. CORS uses an exact configured origin. Cancellation, leases, retries and quotas are durable server decisions.

Scanner memory is frozen policy, default2GiB for old sessions and bounded256MiB–8GiB. New large Browser fixtures publish4GiB through genuine independent governance after an identical-byte2vs4GiB probe. Coverage, rejection and zero-Browser-retry requirements are unchanged.

See [upload API](upload_api_contract.md), [large archive design](large_archive_design.md) and [operational runbook](operational_runbook.md). Raw signed URLs and traces never become public acceptance evidence.
