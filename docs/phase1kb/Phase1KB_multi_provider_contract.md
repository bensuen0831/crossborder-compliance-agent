# Canonical provider/model control-plane contract

Authoritative tables remain Phase1C `model_providers`, `model_provider_versions`, `model_definitions`, `model_deployments`, capabilities and health. Provider/vendor identities differ; duplicate remote model names on different providers are allowed. Independent provider draft commands append existing provider versions; model commands append deployments referencing an approved published provider version. Existing metadata review/publish authorization, lifecycle transitions, publication records and registry sync outbox are reused. Independent approval is required. Current enablement changes are revocations; published configuration changes require a successor version.

Provider protocol is immutable for the provider identity. OpenAI-compatible wire supports chat, structured output, embeddings, streaming and GET models. Structured output format is deployment configuration (`json_schema` or `json_object` with local schema validation), never a vendor/business branch. Unsupported operations fail closed. Discovery is candidate-only and cannot publish a model.

`0016_phase1kb_multi_provider_llm_governance` extends only existing deployment persistence with exact model configuration; provider/deployment published configuration has DB immutability guards. Snapshot-dependent reads use analysis-as-of validity and current access/enablement/health separately. No latest configuration may replace a historical pin.

Control commands use optimistic concurrency. Secret values are excluded from command representations/serialization and all provider views. Provider views return `secret_configured`, never `secret_ref` or the value. All commands are tenant scoped and admin authorized; ordinary users cannot create providers or endpoints. Transport tests and selection gates are measured separately from persistence tests.
