# Owning correction contract

Fact/product selection accepts only canonical choices belonging to the exact pinned context conflict. It creates a successor ProjectVersion and uses existing E owners to resolve a new context version. Original values, document candidates, structured provenance and old ContextConflict remain intact; legacy conflict mutators are never called.

After REQUEST_CHANGES on a production requirement-confirmation task, CLARIFY_INTAKE accepts the existing typed IntakeFacts contract. It cannot change uploaded-document identities or analysis date. Unsupported party/flow/jurisdiction/result edits expose no correction action. Comments are audit text and never formal facts.

All writes require current tenant/project/role permissions, CAS and actor-bound idempotency. Unknown selections and arbitrary legal-result patches fail closed.
