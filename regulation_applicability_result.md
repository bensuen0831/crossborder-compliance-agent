# Phase1I — formal applicability

Phase1I Track: `phase1i-applicability-country-scenario`; verified base `700951ebb9ebdf33e399158fd3fb53bb4a6c87e7` / `v3.6-phase1h-pass`. Frozen implementation SHA: `131d101cdd02999aa478c1a730f492c1729caf30`. DRAFT PR: [#18](https://github.com/bensuen0831/crossborder-compliance-agent/pull/18), target main; no merge. Final validation evidence is recorded in [test_result.md](test_result.md) and `evidence/phase1i`. Earlier-phase sections, where present, remain historical evidence.

Authoritative RegulationApplicabilityResult references the canonical knowledge document/version, regulation structure nodes and LegalBasis. It retains tenant/project/snapshot, subject/data items/flows/scenarios, jurisdiction, as-of/context versions, classification/RuleHit/evidence/pack references, country/scenario/config versions, stable reasons, confidence, review/conflict, fallback and provenance. The only new authority is `regulation_applicability_results`; its canonical foreign keys, retry identity and immutable JSON prevent duplicate results or silent overwrite.

Statuses: APPLICABLE, NOT_APPLICABLE, CONDITIONALLY_APPLICABLE, INSUFFICIENT_EVIDENCE, CONFLICTED and REVIEW_REQUIRED. A reviewed applicability configuration maps required pinned H rule matches through explicit ALL/ANY semantics. Missing hits are insufficient evidence, never a negative legal decision. Contradictory versions/matches/actions for the same rule return CONFLICTED independent of input ordering. Partial/insufficient/conflicted G evidence preserves fallback. Missing legal basis, ineffective source, absent classification when required, missing profile or scenario requirements cannot produce a positive result.

DATA_ITEM uses exact item evidence/H outputs; DATA_FLOW uses validated canonical flow plus linked items and exact flow evidence; SCENARIO requires formal facts/scenario/jurisdiction and independent sufficient project evidence with requires_classification=False. No raw reparse, unpinned rule selection, country classifier or fabricated classification.

POST `/api/v1/projects/{project_id}/regulation-applicability` accepts references only. GET `/api/v1/regulation-applicability/{result_id}` revalidates current access and evidence while preserving immutable output. Presentation is separate at `.../{result_id}/presentation?locale=...`; formal status/reason codes never become localized strings.
