# V3.7 設計一致性檢查與變更摘要

## 結論

本次新增要求與原 V3.6 主架構 **高度一致，不需要重設計**；應以 V3.7 增量收口。

## 原設計已明確支持

1. **Multi-provider LLM Gateway**：V3.6 已要求 `Agent/Skill → LLMService → ModelRouter → ProviderAdapter`，支持 OpenAI-compatible、OpenAI、Azure OpenAI、Gemini、Claude、Qwen、DeepSeek、Internal、Other REST。
2. **Model Usage / Redaction**：V3.6 已有 `EXTERNAL_MODEL_ALLOWED / REDACTION_REQUIRED / INTERNAL_MODEL_ONLY` 與 DataRedaction boundary。
3. **LLM 非正式法律 Authority**：Document Intelligence 只做理解；Risk Score 由 structured rule 計算；LLM Wiki 不是 authoritative legal source；Visualization 不可由 LLM narrative 反解析。
4. **Third-party API 是正式產品接口**：V3.6 已要求 OAuth2/Service Account、Sync/Async、Webhook、OpenAPI、Idempotency、Rate Limit、SDK。
5. **ONE INTELLIGENCE CORE + MULTIPLE ACCESS CHANNELS**：Web / VS Code / Third-party API 共用 Domain Result 與 Application Use Case。
6. **Stage 2 user opt-in**：Regulatory Document Generation / Contract Generation / Auto-fill / Contract Review 只可在 Stage 1 後由用戶確認啟動。

## V3.7 需要新增明確化

1. `RAG-FIRST / RULE-FIRST / EVIDENCE-FIRST / LLM-WHEN-NEEDED` 作正式 LLM 使用原則。
2. `LLMInvocationPolicy`：需求文檔語義抽取、低置信度、知識不足 query expansion、結果解釋、Stage2 文檔/合同生成審核等 typed triggers。
3. 明確 `LLM parametric knowledge ≠ Legal Evidence`；knowledge gap 只能協助重檢索，不能以模型記憶填補 Formal LegalBasis。
4. 支持多 Provider instance、多 endpoint、多 model；增加 GLM/Zhipu-compatible preset，但 vendor 只屬 metadata/adapter。
5. Admin Provider/Model Control Plane + write-only Secret + Test Connection / Model Test / Model Discovery。
6. 用戶模型選擇 `AUTO / SINGLE / MULTI_MODEL`；selection 是 preference，ModelUsagePolicy/ModelRouter 才是 authority。
7. Snapshot pin provider/model/deployment/policy/prompt version identity，不 pin secret。
8. 明確 Southbound Model Provider API 與 Northbound External Agent API 為兩個 trust boundary。
9. Public API canonical Stage1 input/output、async/webhook、UI/API channel parity。
10. Full Stage1 E2E 改為 single continuous business journey；加入前端 Smoke、真實文件、RAG/Evidence、formal results、受控 real LLM trigger、第三方 API path。

## 與 M2-A～M2-D 已驗證實作的一致性

V3.7 保留並提升以下實證 contract：Structured Intake、real binary/parse/source trace、temporal snapshot、CrossBorderAssessment authority、RequiredDocument authority、Stage1 Result Workspace、Human Review/Resume、successor Snapshot、historical immutability。
